# 手作工作室 · 材料包履约台

开课前按「学员报名 × 课程版本」准备材料包，覆盖材料包清单、装箱核对、作品回寄、
烧制/装裱加工、成品返寄全链路。纯 Python 标准库 + 原生前端，零依赖，一条命令启动。

## 启动

```bash
./run.sh                 # 默认 http://127.0.0.1:8000
PORT=8321 ./run.sh       # 换端口
python3 app.py --reset   # 清空并重新播种（内置缺件等异常案例）
```

首次启动自动建 SQLite 库 `data/fulfillment.db` 并播种演示数据；作品照片上传后保存在
`data/photos/`，物流走可替换的模拟适配器（`studio/shipping.py`，运单号 `MOCK-CK/RC/FC`）。

## 已固化的业务规则

- 材料包按报名唯一生成；清单在生成时整包快照，课程改版不改变已发材料包。
- 装箱需主确认人与复核人两名**不同**打包员；`BEGIN IMMEDIATE` 行锁 + 应用锁，
  重复确认与并发确认同一包都只允许一人成功。
- 缺件、未确认替代颜色、未装箱项都会阻止封箱，并各自留痕。
- 去程材料包 / 作品回寄 / 成品返寄为**三张独立运单**；现场自取无运单。
- 缺件、替代颜色、配送破损、迟交、作品运输损坏、返寄地址变更全部写入 `incidents`。
- 损坏签收自动开索赔单；作品损坏索赔成立后工作室才接收受损作品进入修复。
- 成品返寄后拒绝再改地址（需走承运商改派）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：版本锁定、重复打包（含双线程并发互斥）、缺件/替代色拦截、双运单链路、
配送/作品/成品三类损坏索赔、迟交、地址变更、照片落盘与 HTTP 端到端。
